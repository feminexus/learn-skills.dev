Если ошибка связана с именованной сторонней библиотекой/инфраструктурой или симптомы сильно коррелируют с поведением, специфичным для платформы/библиотеки, оцените «обновление зависимости» ПЕРЕД тем, как прибегать к локальным обходным путям. Описывает четырехэтапное решение (является ли оно восходящим? → проверьте журнал изменений/примечания к выпуску → обновление с низким риском семвера → обходное решение только в том случае, если обновление невозможно), дисциплину проектирования обновления (согласованность менеджера пакетов, цепочку проверок после обновления, риск семвера, дедупликацию) и таблицу результатов. Используйте этот навык всякий раз, когда ошибка напоминает проблему с вышестоящей библиотекой — симптомы, привязанные к конкретной версии платформы, скрытые сбои, когда код выглядит правильно, обходные пути, которые продолжают расти, или ошибки рендеринга, специфичные для платформы, которые CSS не может исправить. Триггеры — 「升级依赖」「依赖升级修复」「这个 ошибка 升级依赖能解决吗」「查 журнал изменений Обходное решение / обновление зависимостей, обновление для исправления ошибки, исправление журнала изменений, обход обходного пути, обновление библиотеки для исправления.
