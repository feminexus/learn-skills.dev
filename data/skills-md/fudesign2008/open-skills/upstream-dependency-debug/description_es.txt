Cuando un error involucra una biblioteca/marco de terceros designado, o los síntomas se correlacionan fuertemente con un comportamiento específico de la plataforma/biblioteca, evalúe "actualizar la dependencia" ANTES de implementar soluciones alternativas locales. Recorre una decisión de 4 pasos (¿es ascendente? → consultar Registro de cambios/Notas de la versión → actualizar con bajo riesgo de semver → solo solución alternativa si la actualización no es factible), la disciplina de ingeniería de actualización (consistencia del administrador de paquetes, cadena de verificación posterior a la actualización, riesgo de semver, verificación de deduplicación) y una tabla de resultados. Utilice esta habilidad siempre que un error parezca un problema de biblioteca ascendente: síntomas vinculados a una versión específica del marco, fallas silenciosas donde el código parece correcto, soluciones alternativas que siguen creciendo o errores de representación específicos de la plataforma que CSS no puede solucionar. Activadores — 「升级依赖」「依赖升级修复」「这个 error 升级依赖能解决吗」「查 registro de cambios修复」「优先升级依赖」「升级依赖还是堆 solución alternativa」/actualización de dependencia, actualización para corregir errores, corrección de registro de cambios, evitar solución alternativa, actualizar biblioteca para corregir.
