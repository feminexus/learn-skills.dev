Wenn ein Fehler eine benannte Bibliothek/ein Framework eines Drittanbieters betrifft oder die Symptome stark mit einem plattform-/bibliotheksspezifischen Verhalten korrelieren, sollten Sie „die Abhängigkeit aktualisieren“ prüfen, BEVOR Sie auf lokale Problemumgehungen setzen. Durchläuft eine 4-stufige Entscheidung (ist es Upstream? → Änderungsprotokoll/Versionshinweise prüfen → Upgrade mit geringem Semver-Risiko → nur Problemumgehung, wenn Upgrade nicht durchführbar ist), die Upgrade-Engineering-Disziplin (Konsistenz des Paketmanagers, Verifizierungskette nach dem Upgrade, Semver-Risiko, Dedup-Prüfung) und eine Ergebnistabelle. Verwenden Sie diese Fähigkeit immer dann, wenn ein Fehler wie ein Problem mit der Upstream-Bibliothek aussieht – Symptome, die mit einer bestimmten Framework-Version zusammenhängen, stille Fehler, bei denen der Code korrekt aussieht, Problemumgehungen, die immer größer werden, oder plattformspezifische Rendering-Fehler, die CSS nicht beheben kann.
