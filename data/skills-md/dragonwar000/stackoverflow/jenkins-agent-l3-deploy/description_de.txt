Stellen Sie eine Docker-Compose-App über einen Jenkins INBOUND AGENT bereit, der auf dem Zielserver ausgeführt wird (kein SSH vom Controller), mit Docker-Secrets „L3“-Härtung – Laufzeitgeheimnisse leben auf tmpfs und erscheinen weder in „docker inspect“ noch in „.env“. Verwenden Sie diese Option, wenn der Benutzer Folgendes wünscht: „Bereitstellung über Jenkins-Agent“, „No-SSH-Bereitstellung“, „Agent, der SSH verwendet“, „Docker-Geheimnisse L3“, „Ein Geheimnis für Docker-Inspektion“, „Geheimnis für die Datenüberprüfung“ oder wenn er eine Jenkins-Pipeline verbindet, die Docker-Compose auf einem Linux-Host bereitstellt. Kodiert die Fallstricke, die aus einem echten 1:1-Lauf gelernt wurden (Java 21, 0444 geheime Berechtigungen, 0400 Dateianmeldeinformationen, Agent-Benutzer benötigt Docker+Sudo).
